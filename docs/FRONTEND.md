## 1. 问题的形状：维护成本来自哪里

近几周前端出的问题**不是**"裸写 JS 所以难"——逐条看根因类型：

| 事故 | 根因类型 | 框架能防住吗 |
|------|----------|--------------|
| `/evolution` 导航跑到右边（2026-09-25） | **同一结构有 4 份副本**，其中一份写错 | 不能（任何框架里 4 份手写 header 都会漂移） |
| 线路面板空、城镇面板空（2026-09-23/25） | **后端有数据、却从没发到页面** | 不能 |
| 步骤表每帧 1.8k–2.6k 次 DOM 变更 | **数据量与推送率**（不是框架慢） | 不能 |
| "0 控制台错误"却是假的（MEMORY D45/D51/D53） | **验证方法**（空状态、漏条件、错选择器） | 不能 |
| `null` 被渲染成 `0` | **诚实规则**没被锁住 | 不能 |

**结论**：真正的成本来自**同一个行为要改几处、以及改错时是否静默**。框架不改变这两件事，
**结构**改变。因此先做结构，不先换框架。

规模（2026-09-25）：5 个页面、前端 JS+HTML ≈ 7.3k 行；最大文件 `live-view.js` 47 KB、
`ucharts.js` 44 KB、`common.js` 31 KB、`live.js` 20 KB。

## 2. 四条结构改造（按性价比排序，各自可独立验收）

### S1 页头/导航：一个来源 ✅ 已完成（2026-09-25）

页面只声明 `<div class="brand" data-brand="live"></div>`，内容由 `common.js` 的
`renderChrome()` 生成；守卫 `test/unit/web-assets.test.ts` 断言"任何页面不得手写
`<h1>`/`<nav>`"。**验收**：往任一页面重新手写标题或导航 → 测试红。

### S2 快照契约：一份类型 + 一处转换 + 一处校验

- 后端：`toWireSnapshot()` 是快照的**唯一**转换点（`src/game/wire-snapshot.ts`；
  它的注释记录了"两份实现漂移"的历史——`runner.ts` 与 `game/runner.ts` 各一份，
  后者带 `history`，前者忘了，导致 `--agent`/`--serve` 下现金曲线永远为空）。
- 前端：`live.js` 的 `onSnapshot` 是**唯一**入口，逐字段显式映射。
- **缺的那块**：字段名两端都是手写字符串，"后端加了字段、前端没接"能静默通过。
- 做法：把快照形状提升为一处类型声明（`wire-snapshot.ts` 导出 `WireSnapshot`），
  前端消费处用 JSDoc `@type` 引用；再加一条开发期形状检查，页面拿到未知/缺失字段时
  `console.warn` 一次（不是每帧）。
- **验收**：① 在 `toWireSnapshot` 加字段但不接前端 → 有测试/警告指出；
  ② 前端读不存在的字段 → 运行时给**一次**警告（而不是静默 `undefined`）。

### S3 视图模型：规则留在纯函数里，模板只做字段访问

- 规则：**模板里不做推导**（`x-text` 只允许"字段/方法调用"，不允许三元套三元）；
  任何"给什么状态 → 显示什么"的判断都进 `<page>-view.js`，并**必须**有单测。
- 收益已被证明：`Number(null) === 0`（未知总数被显示成"0 个城镇"）就是被 view model
  的单测抓住的；写在模板里只会表现为"数字看起来有点怪"。
- **验收**：新增/修改页面规则必须同时出现 `<page>-view.test.ts` 用例。

### S4 组件词汇：把重复的 5 种结构变成"可复用 + 可看"

重复结构：`kpi` 卡、`panel`（标题+空态+表格）、`kv` 表、空态行、抽屉。
- 做法：`common.js` 已有 `kpi()` 这类构建器 → 补齐 `panel({title, note, empty, body})`；
  再做开发者目录页 `/dev/components`（只在 `--dev` 下路由），把每种结构在
  "有数据 / 无数据 / 不可得"三种状态下**渲染出来**供人工看。
- 为什么值得：本项目**反复**在"空态与不可得态"上出错（MEMORY D50：加了状态却没给退场；
  `routesAvailable`/`townsAvailable` 都是后补的）。把三种状态并排展示，是把"漏一个状态"
  从"靠人记得"变成"一眼看得见"。
- **验收**：新页面不再出现新的 `<table class="kv">` 手写副本；目录页覆盖三种状态。

## 3. 何时才换框架（触发条件事先写死，避免拍脑袋）

| 方案 | 现在换的代价 | 现在换的收益 | 判定 |
|------|--------------|--------------|------|
| 保持 Alpine + 原生，做 S1–S4 | 低（增量） | 直接消灭上述两类根因 | ✅ **推荐** |
| Preact + htm（无构建链，8 KB + <600 B） | 5 页重写；已有 41 个前端单测要重做 | 组件模型更硬，但没有"组件组合爆炸"的证据 | ⏸ 暂缓 |
| Svelte/Vue（需构建链） | 引入工具链 + 产物陈旧面；违反 D3(b) | 同上 | ⏸ 暂缓（需所有者先改 D3） |
| UnoCSS | 与"结构"无关，见 §6 | —— | ⏸ 见 §6 结论 |

**触发条件**：当同一类**结构性问题**在 S1–S4 之后仍重复出现 ≥2 次，且它的根因被归到
"状态管理与组件复用"（而不是"少一处来源"或"少一条验证"）时，再评估 Preact+htm 这类
**无构建链**方案。

## 4. 已实施的依赖：结论与教训

### 4.1 体积事实（实测：真包装到 /tmp 测 raw 与 gzip，不猜）

| 库 | 版本 | raw / gzip | 依赖数 | 许可 | 需要构建 |
|---|---|---|---|---|---|
| uplot | 1.6.32 | 51 KB / **22 KB** | 0 | MIT | 否（IIFE） |
| alpinejs | 3.17.2 | 56 KB / **20 KB** | 1 | MIT | 否 |
| tom-select | 2.6.2 | 52 KB / **18 KB** | 2 | Apache-2.0 | 否 |
| petite-vue | 0.4.1 | 17 KB / **7 KB** | 0 | MIT | 否 |
| preact | 10.29.8 | 11 KB / **5 KB** | 0 | MIT | 否（JSX 除外） |

零依赖的体积优势仍成立（都是 KB 级）；但**手搓 3,735 行**是维护问题，不是体积问题。

### 4.2 Intl 替换 fmt\* —— 最便宜的胜利 ✅ 已实施

`fmtInt` / `fmtPct` / `fmtAgo` 等改用 `Intl.NumberFormat` / `Intl.RelativeTimeFormat`，
删约 70 行，零依赖。

**教训（必须记）**：**不要让 ICU 决定单位后缀。** `notation:"compact"` 的后缀拼写是
**CLDR 版本数据，不是契约**。实测同一次调用：Node 24 给 `1.5B`，Chrome 149 给
`1.5bn`，本项目 `charts.js` 给 `1.5B` → 同一页面 KPI 写 `£1.5bn`、图表轴写 `1.5B`
**自相矛盾**，换一次运行时就可能再变。

**最终设计**：Intl 只负责数字部分（千分位、四舍五入、小数位）；单位阶梯 k/M/B/T 是本项目
的显式约定（`common.js` 的 `COMPACT_UNITS`，与 `charts.js` 的 `util.fmtCompact` 同一套
词汇）。两条测试守住：① 在**拒绝 compact notation 的敌对 Intl** 下重跑；
② 逐值断言 `fmtTok(v) === charts.util.fmtCompact(v)`。

保留手写的两个：`fmtDuration`（`Intl.DurationFormat` 未普遍可用）、`fmtGameDate`
（游戏历法，不是真实日期）。

### 4.3 uPlot 替换 line/bars ✅ 已实施

- `charts.js` 909 → **573 行**；`line`/`bars`/`stackedBars` 改为委托 `assets/js/ucharts.js`
  （~230 行适配层）包装 vendored uPlot。
- **页面零改动**：适配层保留原配置形状（`{series, labels, format}` / `{items, series, maxBars}`）。
- **堆叠柱自己累加**：uPlot 的 `paths.bars` 从 0 画起，多序列会重叠 → 适配层先把每条序列
  累加再交给 uPlot（有单测锁定，含 NaN 与截断）。
- **tooltip 由 uPlot 图例承担**：启用 `legend.live` 后它列出光标处各序列值，正好替代手搓
  tooltip **和**页面重复的颜色图例（`static/legend` 只留 uPlot 不知道的信息）。
- **离线降级**：uPlot 没加载时清空图表区域而不是抛异常（有单测）。
- **保留自写**：donut / sparkline / stageMap（uPlot 都不做）。
- **vendor 纪律**：`scripts/sync-vendor.ts` 从 `node_modules` 同步，`scripts/verify-vendor.ts`
  用 sha256 校验逐字节一致，已并入 `gate`；`PROVENANCE.json` 是审计台账。

### 4.4 Alpine.js —— 无构建链的唯一主流选项 ✅ 已实施

对比：petite-vue 更轻但维护弱、模板语法不如 Alpine；Preact+htm 需要 JSX/htm 编译
= 引入构建链；Vue/React 必须 bundler。

**实施要点**：页面一个一个迁，每页迁完真机验证再动下一页；`assets/js/alpine-bridge.js`
注册 magic 与 store；`<page>-view.js` 是**纯函数 view model**（可在 `node:vm` 里完整单测），
`<page>.js` 只留 IO 与命令式部件。

**两个真机才暴露的坑（已修）**：
1. **`Object.assign` 会丢类型**：`return Object.assign(model, {...})` 让 tsc 看不见
   `this.data` / `$refs` → 必须用展开 `{...model, ...}`。
2. **响应式读取必须在 effect 的同步作用域内**：`drawDonut()` 把 `tokenSlices()` 写在
   `$nextTick` 回调里 → Alpine 追踪不到依赖 → 数据到达后 effect 不重跑 → 环形图永远不画
   （canvas 存在、painted = 0，图例正常 = 依赖追踪失效的典型特征）。修好后 painted = 223。
   已加回归测试（断言读取发生在异步边界之前）。

### 4.5 组合框：Tom Select 尝试后**回退**（未落地）

**回退原因**：集成后浏览器实测**下拉能打开但选项为空**（功能性回归）。按"每阶段验证通过
才继续"的原则，宁可保留已验证可用的手写实现，也不上线一个坏掉的搜索框。**未提交阶段 3 代码。**

实测细节（若重启阶段 3 用）：① 手写 `<div id="prov-cbx">` 直接交给 Tom Select 是错的
（它把该 div 当 input 隐藏、把 `.ts-wrapper` 插到容器外）→ 必须自己建 `<input>` 放进 host 内；
② 修正后输入可用、下拉能打开，但 `.ts-dropdown` 内 `.option` 数量为 0；
`clearOptions()`+`addOption()`+`refreshOptions(false)` 在该版本不渲染条目；
③ 自定义 render（副标题、分组）也没生效 → 指向"选项没真正进入实例缓存"这一共同根因。

**重启前置条件**：改用构造期传 `options`（或官方 `addOptions()`）；用
`TomSelect.getOrCreateInstance()` 直接断言 `Object.keys(inst.options).length`，
把"选项是否真的进去了"变成可断言目标；先在最小 HTML 页面上跑通"配置形状 → 渲染"，
再接入 providers 页。

**手写 combobox 的已知欠账**（自写部分的真实缺口）：键盘 ↑↓/Home/End/Enter/Esc 部分可用；
模糊匹配**未处理中英混排**；IME 合成态**未处理**（按 Esc 会乱）；滚动到选中项**未做**；
ARIA attributes **只塞了部分**。这些正是 a11y 雷区，也是当初换 Tom Select 的原始动机。

### 4.6 后端：不换（= 0 替换目标）

- `src/web/server.ts` 手搓 HTTP 路由：Node 内置 `http` 足够；Express/Fastify/Koa
  = +50–100KB 依赖 + 新 API + 改错误处理模型 + 重写已有测试 → **不换**。
- `src/game/admin-protocol.ts`：SPEC 锁定的字节协议，核心资产 → **必须自己写**。
- `src/agent/*` 决策/调度/telemetry、`src/game/observer.ts` / `world-state.ts`：
  领域逻辑 → **不换**。
- JSONL 持久化：足够简单 → **不换**。

### 5.2 D3 澄清：被混在一起的两条约束

| 约束 | 到底是什么 | 性质 | 违反后的真实代价 |
|------|------------|------|------------------|
| **(a) 离线 / 不用 CDN** | 产物必须落在仓库里，`file:`/本地服务即可运行 | **硬约束** | 引入 CDN → 离线即坏；已被 `verify-vendor.ts` + `vendor.test.ts`（字节级）守住 |
| **(b) 无构建链** | 不允许"源码 → 产物"的生成步骤 | **偏好**，真实载荷是：*磁盘上跑的就是仓库里的*、*没有会被忘记的生成步骤*、*零工具链* | 多一个 generate 步骤 + 产物会过期（改了源忘了生成 → 页面跑旧的），这是**新的静默失败面** |

D3 是 v0.0.1（`f61b8ba`）的一行决定，**没有记录成本/收益分析**；而且已被放宽过一次
（Alpine.js 是所有者推动后引入的）——即"无构建链"一直按**惯例**执行，而不是按被论证过的规则。

### 5.3 需要所有者决定的一件事（A / B）

- **A（建议）——澄清 D3，不动产物机制**：
  > 允许 **vendored 预构建第三方产物**（带 `PROVENANCE.json` 与字节级校验）；
  > **禁止第一方源码 → 产物的生成步骤**（这才是"会被忘记的生成步骤"的来源）。
  在此规则下：Lightweight Charts / Web Awesome / Open Props / vendored UnoCSS **都允许**；
  Tailwind CLI / Vue / React SFC **不允许**（它们要转译**第一方**源码）。
- **B——正式把 (b) 也放开**：允许前端构建链（Vite + 任一 CSS 框架）。代价：多一个工具链、
  产物会陈旧、CI 与本地都要生成一次。

**A 与 B 的分界不是"能不能用库"，而是"产物是不是仓库里就有"。**

若选 A 的推荐顺序（只在能删掉手写代码时才引入）：① Alpine + uPlot 保持现状（图表交互刚
修好并做过像素级验证，此时换库 = 重写已验收的东西）；② Open Props（可选，仅当要给 CSS
变量一个统一来源）；③ Web Awesome（按需，出现真正的表单/对话框需求时）；④ Lightweight
Charts（条件性：原生十字光标 + 原生缩放工具条被判定为用户可见收益时，且保留现有"图表
健康"断言）；⑤ UnoCSS（先按 §6 的有界实验拿数字）。

## 6. UnoCSS：结论、实测与分阶段方案

### 6.1 结论（先给答案）

1. **不采用 runtime 模式**：不是因为它慢（实测很便宜），而是**载荷账算不过来**——
   它给一个 **10.8 KB gz** 的 CSS 预算再**加 51.5 KB gz**（+4.8×），而它最多能替代的
   样式只值 **约 20% 的 `style.css`**。
2. **若未来仍要引入，唯一合理形态是 CLI 模式 + 提交产物 + 门禁校验**（"生成但被验证"：
   改源忘了生成 → **门禁红**，而不是页面静默变旧）。
3. **当前不建议整站迁移**：可替代比例小、`style.css` 是五页共享文件（搬进 markup 会丢掉
   共享摊薄）、现有小词汇表（`dim`×63、`num`×46、`panel`×24…）**已经在做 utility 该做的事**。
4. 真要推进 → §6.5 的**单页试点**先行。

### 6.2 实测：runtime 模式的真实成本（2026-09-24，跑在真实运行中的 dashboard 上）

方法：同一页面、同一批 DOM 突发（200 元素 × 20 个 utility 类，插入→移除），有/无
`uno.global.js`（v66.10.5，npm 包字节）各测 7 次取中位；另开平行 WebSocket 数**真实推送
帧数**（把"每帧成本"与"帧率"分开——上一轮测量失败的根因）。

| 指标 | 无 runtime | 有 runtime | 结论 |
|------|-----------|-----------|------|
| 突发耗时（中位） | **0.70 ms** | **1.20 ms** | 重扫 **+0.5 ms / 200 元素**（≈0.0025 ms/元素） |
| CSS 规则数 | 320 | 347 | 只增加**被用到**的生成项 |
| 实时 10 s 窗口（runtime 在场） | — | 规则增量 **0**；长任务 **1 次 / 57 ms** | **没有**"每次 DOM 变更重算 CSS"的迹象 |
| 实时窗口的页面变更 | — | **125,277 次节点操作 / 10 s = 12.5k/s**，49 帧 | 与用户报的 ~17k/s 同量级 ✓ |

因此"runtime 有 #4766 风险"这条早先担忧**在 66.10.5 上未复现**：重扫便宜、且不重算已生成
规则。**否决 runtime 的理由是载荷，不是速度。**

同时修正一个测量错误：当时在新局（仅 17 行事件）测得"稳态只有几百/10s"并据此怀疑 churn
很小——那是**低数据量下的假阴性**（MEMORY D53/D59 同型）。真实长局是
**2,557 次变更/帧 × 4.9 帧/s = 12.5k/s**。

### 6.3 实测：可替代比例（决定 payoff 上限）

| 项 | 数值 | 含义 |
|----|------|------|
| HTML/JS 引用的类名 | **160** | 以语义组件类为主 |
| `style.css` 单类规则 | **114 条 / 11,046 字节**（规则体） | 只有这部分**可能**被 utility 表达 |
| ├ 被复用 ≥5 次（真组件，**保留**） | **16 条 (15%)** | `dim`×63、`num`×46、`panel`×24、`kpi`×16 |
| ├ 被用 ≤1 次（**可内联为 utility**） | **78 条 (67%)** | 主要是 `act-*`/`cbx-*`/`arm-*` 这类一次性结构 |
| └ 本次扫描未引用 | 24 条 (14%) | **未证明是死代码**（可能在 `index.html`/动态构造里），需人工确认 |
| 状态 / 后代 / 属性选择器规则 | **~180 条** | utility **无法表达**，必须留在 CSS 里 |

**上限**：可替代部分 ≈ **style.css 的 20%**；且与共享摊薄冲突——`style.css` 是**五页共用的
一个文件**（10.8 KB gz 摊到 5 页），搬进各页 markup 意味着每页各付一次。

### 6.4 三方案对比

| 方案 | 载荷 | 工具链 | 静默失败面 | 判定 |
|------|------|--------|-----------|------|
| **A. 不迁移**（现状） | baseline | 无 | 无 | ✅ **推荐**（除非 §6.5 试点证明有净收益） |
| **B. runtime** | **+51.5 KB gz**，是可达节省（≈2.2 KB gz）的 **23×** | 无 | JS 动态构造的 **22 个类名**要等重扫才生效 → 首次出现会**闪一下**（FOUC） | ❌ **否决**（载荷） |
| **C. CLI + 提交产物 + 门禁校验** | 只含**实际用到**的 utilities（预计 1–3 KB gz） | 需要一个**生成步骤** | 忘了生成 → **门禁红**，不是静默变旧 | ⚠️ **唯一可能划算的形态**；需所有者放行 D3(b) |

**方案 C 为什么能绕开 D3 的本意**：D3 的真实载荷是*"磁盘上跑的就是仓库里的" +
"没有会被忘记的生成步骤"*。把 `uno.css` **提交进仓库**、并加一条门禁命令"重新生成到临时
文件 + 字节比对"（与 `verify-vendor.ts` 同一模式），就同时满足两点。**代价是必须放弃
"零工具链"** → 需要所有者决定（§5.3 的 A/B）。

### 6.5 若选 C：风险清单与分阶段方案

**风险（先钉死）**：① **JS 构造的类名（22 处）**：CLI 抽取是文本级的，拼接出来的类名
（如 `'k'+i`）抽不到 → 必须 **safelist**，并加测试断言"所有 JS 构造的类名都在生成的
`uno.css` 里"；② **FOUC**：CLI 模式生成静态文件，无重扫延迟 ✓；③ **令牌漂移**：现有
**39 个 CSS 变量**必须成为 UnoCSS `theme` 的**唯一来源**，否则出现"两套颜色各改一半"；
④ **不要动状态/后代规则（~180 条）**：强行改写会破坏 `:hover`/`:focus-visible`/
`[hidden]`/`::before` 等语义与可访问性；⑤ **改变共享摊薄**：试点必须**逐页量载荷**。

| 阶段 | 做什么 | 验收（可执行） |
|------|--------|----------------|
| **U0 试点（一页）** | 选 **Providers 页**（最小、无图表）：接入方案 C，把该页 ≤1 次使用的类改为 utility | ① 该页 gz 载荷**不增**（对比 `Content-Length`）② `pnpm run dashboard:smoke` 绿（全部控制台级别 + 有数据状态）③ 人工逐个交互点一遍（AGENTS §5.2） |
| **U1 令牌统一** | 39 个 CSS 变量成为 theme 单一来源 | 单测：`style.css` 变量与 theme **双向一致**（改一处即红） |
| **U2 逐页替换** | 只动"≤1 次使用"的规则；组件类（≥5 次）不动 | 每页：`style.css` 缩减字节 > 该页新增 utility 字节；§5.2 全绿 |
| **U3 门禁化** | `pnpm run uno:check`（重新生成 + 字节比对）进 `gate` | 故意改一处标记 → 门禁**必须变红**（守卫自证，MEMORY D49/D53） |
| **停止规则** | 任一页载荷增加或 0 net 缩减 → 停下，保留现状 | 记录实测，不留"半迁移"状态 |

### 6.6 待决项

**D3(b) 是否放行**（即方案 C 需要一次生成步骤）：

## 7. 不建议的项（说清楚为什么）

| 候选 | 不选的理由 |
|---|---|
| Chart.js / ECharts | 太重（200 KB+ / 1 MB+），能力溢出 |
| TradingView lightweight-charts | 专为金融图设计，绑死 OHLC/candlestick 模型 |

| Lodash / date-fns / dayjs | 没用上 / Intl 已覆盖 / 没有不可替代的功能 |
| immer | state 简单到不需要不可变数据结构 |
| zustand / pinia | 没用上 |

## 8. 原则

- **零依赖本身不是目标**。目标是：**维护成本 < 引入成本时不要引入依赖**；当这个不等式反转
  （已经在反转）就要修，并**显式提出来让所有者确认**，不沉默维持过期假设。
- **vendor 而不是 CDN**：所有依赖 vendored 到 `src/web/public/assets/vendor/`，保持离线可用；
  `scripts/sync-vendor.ts` 同步、`scripts/verify-vendor.ts` 字节级校验（已进 `gate`）。
- **每个阶段独立可回滚**：独立 PR、独立验证、独立可拒绝；门禁（typecheck + lint + test）
  始终不变。
- **回归用真浏览器**：headless Chrome 截屏 + 颜色采样，验证图表画了**对的东西**
  （不只是"没抛错"）。
- **不批量迁移**：一次一个页面/一个库。
