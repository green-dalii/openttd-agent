# Harness 审计 — 2026-09-26（第一性原理）

> 起因：所有者对 Harness 效果不满——两处都不满意：Dashboard 的呈现、agent 的训练效果。
> 本文是审计记录：结论 / 证据 / 根因 / 方案。方案待所有者批准后进 `ROADMAP.md`。
> 写法：80% ASD-STE100（短句、一句一事、主动语态、常用词、术语固定）。

---

## 1. 结论（先说）

1. 不满有证据。训练效果差。Dashboard 也答不了「变强了吗」。
2. 根因不是缺功能。根因是**三个结构性缺口 + 一串仪表谎言**。
3. 最大杠杆是还架构债：**把执行器搬进 GS**（`docs/EXECUTOR-ARCHITECTURE.md`）。
   这一步同时改善训练效果与可视化。
4. 那份架构计划写于 2026-09-12。它有源码级证据。它的阶段 2–4 **从未执行**。
   两周里我们一直在给它的症状打补丁（最近一次：W3 的 31 字符错误分块协议）。

| # | 条件 | 现状 | 判定 |
|---|------|------|------|

## 3. 发现（现象 / 证据 / 根因）

### F1 世界视图长期撒谎（打 C1）

| 仪表谎言 | 实测证据 | 状态 |
|---|---|---|
| `delivered` 是当季计数器，被当累计用 | SPEC §10.65 | ✅ 已修 |
| GS `route_stats` 部分失效，单局丢 1–92% 读数 | SPEC §10.66（17/17 局命中） | ✅ 已修 |
| 世界时钟来自 `Monthly` 订阅 ⇒「WORLD frozen」误报 + agent 看到过时日期 | SPEC §10.102 | ✅ 已修 |
| 车队跨线路重复计数（同屏 25 辆与 129 辆） | SPEC §10.105（真机 12 → 去重 3） | ✅ 已修 |
| 等待量按站重复 | 同上 | ✅ 已修 |
| `transported` 的 -1 被折成「运了 0 吨」 | **本次探针：548 个负读数被折叠** | 🔵 GS 侧未修 |
| 城镇名缺失 ⇒ 线路端点只有 `#4 → #8` | 本次探针：`GSTown.GetName` 存在（"New Badworth"） | 🔵 在飞 |
| 车辆「在途/在库」不可见（线路端点只数停着的车） | SPEC §10.105 契约说明 | 🔵 需新通道 |

**根因**：事实从 GS 到页面/上下文的每一层都可以**悄悄折叠缺失值**。
`Number(x) || 0`、`if (trans < 0) trans = 0` 这类折叠没有守卫。
**推论**：agent 一直在错误事实上做决策。训练效果差是必然结果。

### F2 动作面窄，效果长期不可归因（打 C2）

- 动作面盘点（SPEC §10.80）：环境只有 5 类标牌；运营期唯一杠杆是 `V:<count>`。
- 归因两次被真机证伪：施工期车队请求**永不生效**（§10.81）；`foreach` 取下标
  ⇒ 车队会计数错、卖错车（§10.84）。修前 agent 的「加车」在很多局里是空操作。
- 未结案：`fleetsend8` 卖 4 辆、另 4 辆静默消失（具名 `g<gone>`）。
- 一局里**有后果的决策只有 1–3 个**（2026-09-18 诊断，cal2 六局）。

**根因**：「工具必须真能改变世界、或明确拒绝」（铁律 7）此前没有回归测试兜底。
现在有守卫，但**动词太少**——玩法上限由动作面决定（MEMORY D32）。

### F3 架构选错，被证伪的约束仍在决定设计（打 C2，最大杠杆）

`docs/EXECUTOR-ARCHITECTURE.md`（2026-09-12）用 OpenTTD 源码证明：
「AI 不能收 admin 消息」**这条约束根本不存在**（`script_companymode.hpp`）。
Executor AI + 标牌邮箱带来三个永久残疾：

1. 命令经标牌（Tile 文本）中继 ⇒ 只能传极短字符串。
2. 回报只有公司名 31 字符 ⇒ 无结构化反馈、无错误原因。
3. AI 是一次性状态机 ⇒ 扩动作面受制于 `.nut` 补丁。

**证据：我们仍在为残疾 2 还债**。W3（2026-09-25）为传一段完整错误文本，
实现了 31 字符分块协议（seq + 粘滞 + 指纹 + 截断标记）。它能用。它是补丁。
同一天的车队重复计数、`transported` 折叠，也都源于「数据在 Squirrel 侧被压扁」。

**阶段 2–4（搬执行器进 GS / 删标牌邮箱 / 扩动作面）从未执行。**

### F4 统计上测不出进步（打 C3）

- 第一次 A/B 无效（agent 无决策可做，§10.31/§10.32）。
- 唯一有效对照（§10.42）：**记忆无收益**；下单率是主方差源。
- 自由局 CV 0.57–0.79；+20% 效应**不可检出**；+40% 需 ~36/臂 ≈ 19 h。
- G7 实测：horizon=30 的 19 局 `deliveredRun` 全 0 ⇒ 判据会退化成常量。
- `compareArms` 排除（暂停/冻结/未达窗口）+ 场景混用 ⇒ 可比局很少。

**根因**：任务结局被施工抽签 + executor 吞吐主导（2026-09-18 第 3 层诊断）。
方差在**被测对象**里，不在仪器里（D16）。

### F5 经验回路无有效性证据（打 C4）

- 通路全在：lessons 注入、reflection、`recall`（M4a，真机被调用 2 次）。
- 但：记忆 A/B 无收益（§10.42）；M4b 选择压力未做；M5 学习曲线未跑。
- 结论：「经验让 agent 变强」目前**没有任何证据**。通路 ≠ 效果。

### F6 每局成本太高（打 C5）

- 用户 5 年局（实测 2026-09-26）：**9.15M tokens、691 次决策、80k 事件**。
- 单局 82% token 花在轮询空转（cal2）。
- 25 臂 ≈ 16–19 h ⇒ 跑不起样本 ⇒ C3 永远出不了结论。C5 卡死 C3。

### F7 Dashboard 是运维台，不是训练台（打 C6）

- 三页测的多是 harness 运行量（tokens/steps/decisions/events）。
- 缺：跨局成绩曲线、动作成功率、排除原因的一等展示、「这局值不值得看」的答案页。
- 用户的原始投诉（车队矛盾/不自动更新/无区间/信息少）都是同一类问题：
  **「这个数字是什么意思」**。近两周修的是诚实性（对，且必须），
  但没有回答「变强了吗」。
- 仪表谎言（F1）让可视化不可信；这是不满的直接来源。

### F8 代码质量：门禁盲区 + 复杂度热点

| 问题 | 证据 |
|---|---|
| `scripts/*.ts` **不在 type 门禁内** | `tsconfig.json` include 只有 `src`+`test`；`run-experiment.ts` 存活 **25 个真 TS 错误**（shazam 2026-09-26 抓到）。它恰是实验判据脚本 |
| 复杂度热点 | `runV02`=138、`WebServer`=95、`makeSignalHub`=75、`runAgent`=73、`compareArms`=68 |
| 「声明了但没接线」反复出现 ≥4 次 | `companyCards`、providers 开关、`x-ref`、`--second-route`（MEMORY 有案） |
| DOM churn 12.5k/s | 实测 2,557 mutations/frame（事件列表整块重建） |
| shazam orphan 噪音 25 个误报 | 页面脚本经 `window`/模板消费，静态图看不见 ⇒ 真问题被淹没 |

## 4. 方案（三档；每条带验收）

### P0 — 立即（1–2 天，无架构争议）

| # | 做什么 | 验收 |
|---|---|---|
| P0-1 | 完成在飞事实修复：城镇名（在飞）+ GS 侧去掉 `transported<0→0` 折叠 + 车队口径（已做） | 仪表与事件流一致；`gate` + `dashboard:smoke` 绿；真机截图核对 |
| P0-2 | `scripts/` 进 type 门禁并修 25 个错误 | 故意引错会被 `gate` 抓到（重放证明） |
| P0-3 | Dashboard 第一屏改**训练台**：跨局 `deliveredRun`/游戏日 曲线（按 `scenario` 分组）、排除局及其原因一等展示、每工具成功/拒绝/空转计数 | 一个页面能回答「变强了吗 / 为什么这局不算」；真机截图核对 |

### P1 — 结构（1–2 周，最大杠杆）

| # | 做什么 | 验收 |
|---|---|---|
| P1-1 | 执行器搬进 GS（`EXECUTOR-ARCHITECTURE.md` 阶段 2–3）：删标牌邮箱与公司名通道 | 错误全文以类型化事件到达；每线路车队 = 引擎真值；31 字符协议**删除**（不是弃用） |
| P1-2 | 动作面扩：选货 / 换车（M3-2 遗留） | 每动作过 D4 三问 + 真机双向可归因；未验证 API 不进 SPEC（D43） |
| P1-3 | 每线路真实归因（车辆在途/在库可见） | `FLEET` 的分解能对上公司总数，差额具名 |

### P2 — 测量（跟随 P1）

| # | 做什么 | 验收 |
|---|---|---|
| P2-1 | 预建场景默认（S1 已验证）+ 300 日短局多跑 | 每小时局数 ≥3×；CV 显著下降或明报另有方差源 |
| P2-2 | M4b 选择压力 + M5 学习曲线（预登记） | verdict 打印每条经验的使用局成绩分布；斜率 CI 或「不可判定」声明 |
| P2-3 | 统计预登记写死：MDE 反推 n；+20% 声明为不可检出 | `run-experiment.ts` 跑前拒绝不够 n 的比较（已有 G7 同型先例） |

### P3 — 卫生

删 `v02-runner` 死代码（NEXT-6）· DOM churn 降噪 · shazam orphan 规则修。

### 明确不做

不写策略进提示词；不靠加样本换结论（结构性方差）；不给未验证 API 记功（D43）；
不在仪表谎言修完前宣称任何训练结论。
