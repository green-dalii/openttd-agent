## 1. 问题的形状：为什么现在必然是打补丁

今天一个动词要活起来，要**同时**改动六个地方（全部已实测过代价）：

| 位置 | 内容 |
|------|------|
| `src/agent/tools/index.ts` | 工具定义 + zod schema（模型看到的那份契约） |
| `src/types.ts` | 命令类型 |
| `src/game/squirrel/bridge-gs/main.nut` | `Dispatch(obj)` 的 **if/else 分支** |
| 标牌语法 | `NUTZ:bp:<job>:<type>:k=v` —— **Executor 是另一个 Squirrel VM**，只能靠标牌通信 |
| `src/game/squirrel/executor-ai/main.nut` | 解析分支 + 执行 + 跨 tick 状态机 |
| `src/game/executor-status.ts` | 相位字符串解码（人读的 `EX <phase>`） |

**代价已经真实发生过**，不是理论担心：
- **D20**：给非当前线路调车队被 `fleet_otherjob` 假拒绝 → agent 学到错误因果；
- **D34**：源码里存在分支 ≠ 可达（call-site guard 挡住了）；
- **D41**：声明 → 赋值 → 聚合点，断在最后一环，**静默**。

结论：问题不在"动词太少"，而在**动词的表示散布在 6 处、且没有单一事实源**。

## 2. 第一性原理：通道能消灭什么、不能消灭什么

**能消灭**：每个动词一次的接线成本、表示漂移、"声明了没接线"这一类静默 bug。
**不能消灭**（硬边界，属引擎物理，不是我们的设计）：

1. **引擎能力上限**：GS/AI 只能通过引擎命令队列行动——company mode、金钱约束、
   城镇许可、地图合法性、tick 预算。通道不能让引擎做它没有的能力。
2. **两个 Squirrel VM 的隔离**：Bridge GS 与 Executor AI 是**独立 VM**，
   它们之间只能通过游戏内可见对象（标牌/公司名/事件）通信——所以必须有**线格式**，
   而线格式一旦要兼容就冻结了——因此**线格式必须是通用的、可扩展的**，这正是总线的价值。
3. **异步性**：多 tick 动作（施工、卖车）无法在一次调用内完成 → 通道必须把
   **生命周期**（accepted → running → done/failed）变成一等公民，否则 agent 分不清
   "排队中"和"完成了"（D34 的同类错误）。

三条**不可协商的不变量**（写进通道，而不是写进每个动词）：

- **I1 观测或具名拒绝**：每个动作必须回报自己的效果（引擎真值），或明确说"没观测到"。
  *不许*有"返回成功但状态没变"的动词（D37/D40）。
- **I2 未知动作具名失败**：`unknown_action<name>`，绝不静默忽略。
  静默忽略正是 agent 学到错误因果的作坊（D20）。
- **I3 目录由代码派生**：线格式、分发表、工具 schema **三者同源**，并有测试守卫三者一致。
  这把 D41 类 bug 从"靠纪律"变成"结构上不可能"。

## 3. 设计：三个构件

### (a) 动作信封（envelope）

```jsonc
{ "op": "build_road",  "job": 101, "args": { "from": [x,y], "to": [x,y], "bridge": true } }
```

标牌线格式（Executor 车道）：`NUTZ:act:<job>:<op>:k=v,k=v`；
现有 `NUTZ:bp:` / `NUTZ:...:V:n` 作为 **legacy 语法继续解析**（不破坏已跑通的验证）。

### (b) 能力目录（catalog）

由代码里的一张 `ACTIONS` 表生成：

```ts
{ op: "build_road", lane: "gs", params: <zod>, lifecycle: "oneshot",
  effect: "engine_truth",          // I1：怎么观测效果
  macro: ["build_bus_route"] }
```

暴露为**只读工具 `capabilities()`** → 这直接回答 **D32**（"问环境暴露了多少动作"），
也让 agent 不必猜自己能做什么。**目录必须先于执行落地**：它零风险、零执行路径改动。

### (c) 统一入口 + 宏

- 低层：`perform_action(op, args)`（走目录校验 → 分发 → 生命周期）。
- 高层：**保留** `build_bus_route` 这类高频动词为**宏**（macro = 目录里的组合），
  因为把 3-5 次低级调用压成 1 次调用，对**每局 6 次决策的带宽**是净收益。
  宏与低层**共享同一条通道**——这才是不打补丁的关键。

## 4. 与 pi-agent-core 的协同（本仓库最欠的一块）

`SPEC.md` §10.82 的能力审计结论：**整层 `AgentHarness` 未被使用**。
总线恰好落在四个已存在但我们没用的接口上：

| 框架能力 | 总线用途 | 为什么这比自研好 |
|----------|----------|------------------|
| `setActiveTools` | **能力协商**：目录 → 运行时激活的工具集（按阶段/资金收缩或放开） | 框架原生；我们自己写开关就是又一层补丁 |
| `AgentToolResult.details` | **效果观测的落点**：`{ok, observed:{before,after}, lifecycle}` | 框架已把 blocked/throw 归一为 tool error → I2 的具名拒绝直接映射 |
| `AgentHarness` session（fork/commit/typed values） | **反事实回放**：在决策 k 分叉，"同一局面、不同动作" | 这是从"观测性学习"走向**因果学习**的唯一现实路径；框架已提供 |
| skills / prompt templates | **演化知识的正确容器**（过程性策略归 agent 所有、可改可回滚） | 把"harness 给事实、不给策略"从**纪律**变成**结构**：策略存在 agent 侧 |

**关于 skills 的 D4 判定**（必须先说清）：skill 是一条**新的注入通道**，
因此必须与其它通道同等对待——进 ledger、受 `--no-memory` 类开关控制、在控制判据里披露。
"框架提供了"不等于"可以直接用"（D27：库的默认值不是契约）。

**反事实回放为什么是学习曲线的正解**：跨局 A/B 需要 ~36 局/臂 ≈ 19 小时（G7/pbcal）。
而 savegame + 固定 seed 是**确定性**的：同一存档、同一决策点、动作 A vs B，
两个分支的差就是该动作的因果效应——**这是 G7 那条"cvritain 阈值"唯一能被绕开的路径**。
代价：每个分支仍要跑到可比地平线（≥180 天），但**方差小得多**（同一初始状态）。

## 5. 迁移计划（每步都有真机验收，不新增平行系统）

| 步骤 | 范围 | 验收 |
|------|------|------|
| **0** | 探针：`probe_cm` 全链路（GS 能否**买车**） | 真机：公司名下多出 1 辆车 + 账扣钱 → 决定车道布局与 NEXT-4 可行性 |
| **1** | `capabilities()` 只读工具（目录从现有代码**派生**，含 3 条一致性守卫） | 单测：目录与 GS `Dispatch` 分支、标牌语法、工具名单三者一致；重放证明守卫非空 |
| **2** | `perform_action`（**GS 车道**先行：设施/经济类原语，一 tick 可完成） | 真机：一个此前没有的动词被 agent 用出来，且**观测到效果**（I1） |
| **3** | Executor 车道迁移到同一信封（载具类 + 生命周期） | 真机：`accepted → running → done` 三段可见，且旧标牌语法仍工作（兼容性测试） |
| **4** | pi-agent-core 侧接上：目录 → `setActiveTools`；结果 → `details.observed` | 单测：激活集合随目录变化；live：`--agent` 仍过 AGENTS §5.1 八条 |
| **5** | **反事实回放**（session fork × savegame），独立一轮 | 同一决策点两分支，记录动作的因果差；预注册停止规则 |

**顺序理由**：1 零风险且立刻解决"agent 不知道有什么动作"；2 验证通道本身；
3 才动最危险的多 tick 执行；5 最大且改实验方法，必须独立。

## 6. 风险与反风险

| 风险 | 反风险 |
|------|--------|
| 通用通道**放大信用分配难度**（动作空间↑ → 归因↓） | 先落 M4b（按动作记结果）；每个动作自带 `effect` 字段，与选择压力**同源数据** |
| 目录与实现漂移 | I3 守卫：三者一致性测试 + 从表生成 schema + 重放证明 |
| 通用通道变成"什么都允许"的安全洞 | I2 具名拒绝 + 目录白名单；**不引入 Squirrel 动态求值**（引擎不允许任意代码注入，也不该允许） |
| Legacy 标牌语法被无声改坏 | 兼容性测试：旧语法样本（真实日志 fixture）必须仍解析 |
