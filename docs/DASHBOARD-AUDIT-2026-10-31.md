## 0. 一句话结论

四页的功能面已经齐了（B1–B6），但**呈现面还是"数据表"而不是"仪表盘"**：
问题不是缺功能，而是**同一屏里没有主次、没有图、状态与结论被埋在等权的卡片里**。

| A14 | Configure | "WHERE THIS IS STORED"（文件路径/权限模式）与业务表单同层 | 开发者信息混进了用户页面 |

## 2. 第一性原理：这个界面到底要回答什么

界面不是"展示所有字段"，而是**让人在 5 秒内回答一个问题**。四问各自的问题与应有的**视觉主角**：

| 页 | 问题 | 视觉主角（应当唯一） | 其余内容的位置 |
|---|---|---|---|
| Run | **现在这局在干什么、值不值得继续** | 一条**时间轴图**（游戏日历 × 钱/车队/交付） | 旋钮、诊断、日志 → 折叠 |
| Compare | **谁更好，好在哪一轴** | 每轴一个**横向条形/点图**（模型 × 轴值） | 排除原因、配对判定 → 折叠 |
| History | **这一局发生了什么/哪一局值得看** | 一张**按时间/结果排的局列表 + 选中局的结论头** | manifest、步骤、记忆 → 折叠/二级页 |
| Configure | **下一局会用什么** | 一个**摘要卡**（模型/上限/花费）+ 差异高亮 | 输入项、文件路径 → 次要/折叠 |

三条通则（与仓库既有原则一致）：

1. **一个数字只出现一次**，且必须带它的单位与状态（实测/未测到）。
2. **状态色只给状态**：连接陈旧用中性色 + 文案，不用最亮的红。
3. **"没测到"在视觉上必须与 0 不同**（虚线/斜纹/空心点 + 文案），这是 D60 的视觉版。

## 3. 优化方案（按"能立刻看出差别"排序）

### P0 — 结构与层级（不动数据，只动呈现）

> **实施状态（2026-11-01 完成；改了什么以 `CHANGELOG.md` 为唯一权威）**：
> ✅ 全部 P0 已落地 —— Run 三步引导 + 顶栏瘦身 + 时间轴主角（#66）、
> History 三段式（#67）、Configure 摘要卡 + 空选择不报假警（#68）、
> Compare 每轴一图 + 选择器置顶（#57/#60）。P1/P2 的剩余项见 `ROADMAP.md`。
> 本文件保留当时的判断与方案，**不维护进度表**。

1. **Run 页**：空态重排为「**三步引导**」（① 选模型 → ② 设上限 → ③ 开跑），把 13 个 "—" 收成一个引导卡 + 一个折叠的"世界状态"区。
2. **Run 页**：**加一条时间轴图**（已有的 `money/vehicles/stations` 历史 + 游戏日期）：横轴游戏日，纵轴钱；决策点作为竖线标注（决策 → 工具 → job → 效果，B3 已有数据）。运行中它是主角，空态时不出现。
3. **顶栏瘦身**：品牌/导航一行；状态 chip 只留 **连接** 与 **运行** 两个，其余（数据时间、会话、游戏日）移入页内；按钮按上下文出现（无局时只有"开跑"）。
4. **Compare 页**：四轴改成**每轴一张图**（模型 × 轴的横条；`not measured` 画空心/斜纹，不画 0 长度实心条）；**模型选择器移到页面顶部**（永远可见，选两个即出配对判定）。
5. **History 页**：分成三段——① 顶部 4 个结论型 KPI（可比局/中位交付/token/花费，未测到写 not measured）；② 局列表（紧凑行 + 结果徽标 + 分组）；③ 选中局的**结论头**（outcome + 交付 + 关键读数） + 折叠区（manifest / 步骤 / 事件日志 / Memory）。目录与粘性摘要补上。
6. **Configure 页**：左右改 1:2（表单窄、预览宽）；**NEXT RUN 空选择不报错**（改成引导文案）；文件路径信息折叠进"实现细节"。
7. **A15**：把 `/providers` 重定向到 `/configure`，或把导航改名为 Providers——二选一，全站统一。

### P1 — 数据可视化（用已有的图，不新造指标）

| 位置 | 图 | 数据来源（已存在） | 读法 |
|---|---|---|---|
| Run | 钱/车队随游戏日 | `companies[].history`（world-state 已有） | 一眼看出"这局在变好还是变差" |
| Run | 决策时间轴 | `causal-timeline`（B3） | 一次决策一行：工具/job/效果 |
| Compare | 四轴横条 | `compare-view`（B4，服务端算好） | 谁在哪一轴领先 |
| Compare | 结局分布 | `OUTCOME_CLASSES` 计数（B5） | 这个模型常在哪类结果上失败 |
| History | 交付/局对比 | `metrics.jsonl` | 跨局趋势 + 被排除的局用空心点 |
| History | token 构成 | 已有的环形图 | 输入/输出/缓存/推理 |

**图的三条纪律**（沿用 D48/D51 与 `dashboard:smoke` 的现有守卫）：
- 尺寸/容器实测（不许用"有像素"当"看得见"）；
- 振荡类缺陷必须用**时间序列**断言；
- 固定 `devicePixelRatio=2` 复现用户条件。

### P2 — 一致性与文案

- 中英混排（`FOUR AXES PER MODEL 成绩 / 效率…`）：统一成英文（或统一成中文）——**待所有者定**（§5）。
- "not measured / not determinable / unknown" 在所有页面用**同一套视觉语言**（空心 + 斜纹 + 同一措辞）。
- 空态文案不替通道说话：没读到 ≠ 没有（D84）。

## 4. 验收方式（沿用 AGENTS §5.2，缺一不可）

1. **真实 Chrome + 有数据的状态**采集（不是空态）：四页各 ≥1 张截图 + **全部级别**控制台 0 条。
2. **可见性断言**写进探针：主角图真的在屏上（容器高度 > 阈值）、控件**可见**（不只是 DOM 里存在）、`not measured` 真的画成非 0 长度。
3. **人工过一遍**每个交互元素（AGENTS §5.2 第 4 条）：分组、选择器、折叠、对比勾选、模式切换。
4. **自己看图**（AGENTS §5.2 第 7 条）：数值探针看不见"空白图""标签被裁""幽灵占位"。
5. `pnpm run gate` + `pnpm run dashboard:smoke` 双绿。
