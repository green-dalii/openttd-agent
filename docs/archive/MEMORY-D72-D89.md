### D72（2026-10-24）重构时"提取公共件"必须一次到位：半提取会让文件语法崩掉

**现象**：把 `transformContext` 从 `createAgent({...})` 里提取成独立常量、再给两条 后端复用时，我先插入新声明、后删旧字段，中间那一刻文件是 `const x = foo({...}),` 这种
**语法都不成立**的状态；`tsc` 连报 10 个错（`Trailing comma not allowed`、找不到符号），
其中大部分与真实问题无关，是半成品噪声。若在这时切走（或被 compact 打断），下一个
session 会看到一堆互相矛盾的错误。

**根因**：编辑顺序按"先加后删"，而两处之间存在**语法耦合**（对象字面量的尾逗号）。

**规则**：① 结构性重构先算清"新旧两处的完整边界"，用**一次替换**完成迁移；
② 若必须分步，先让**旧处保持合法**（加新声明时旧字段继续存在但指向新变量），
再单独删；③ 每次 `tsc` 报错超过 3 条且包含语法级错误（TS1005/TS1009）时，
**先怀疑自己处于半成品态**，不要逐条去"修错误"。

### D74（2026-10-24）同一份数据被"按字段重建"三处 = 新增字段必丢一处

**现象**：`manifest` 在 session finalize、`toGameMetric`、reflect-run 入参三处各自 按字段重建。D3b 加 `manifest` 时丢过一次；D6b 加 `payloadHash` 时**又丢了一次**， 而且这次更隐蔽：`meta.json` 里有（我在真机上看到日志与文件都正常）， 但 `metrics.jsonl` 里没有 —— 而分数卡只读后者。也就是说"真机验证通过"验证的是
**另一条路径**。

**根因**：同一份结构在三处独立列举字段（三张白名单），任何新增都要求改三处，
但没有任何机制强制。真机只覆盖其中一条写入路径时，缺失不会被发现。

**规则**：① 一个结构只有一个**投影函数**（这里是 `projectManifest`）和一份字段清单
（`MANIFEST_FIELDS`），所有写入点都调它；② 守卫测试用**字段清单**遍历断言
"经过每个写入点后字段都还在"——不要逐个字段手写断言，那样下次新增还是要手改；
③ 看到 `X: {...}` 出现在两处以上，先问"这是一份数据的两个投影吗"，是就合并。

### D75（2026-10-24）"红测试"的两种死法：用错 API 等一个永远不会来的事件；失败后不清理

**#22 的真相**不是"太慢"，而是**用错握手**：`AdminClient.connect()` 是**一次性**尝试，而 OpenTTD 在地图
生成期间就开着 admin 端口——JOIN 在自举窗口里被踢是常态，`connectAuthed()` 才是带界重试的那个。
测试用 `connect()` 之后死等 `isAuthed()`，于是"超时"只是表象，真实状态是**连接早已被踢**。

**第二个死法**：断言失败时 `finally` 只删目录、不停服 → 残留 OpenTTD 占着 3977/3979，
下一次 `pnpm run gate` 的 `gameRunIsLive()` 判定"真机局在跑"，**静默跳过 13 条 preflight**。
测试失败还能看见，门禁悄悄变窄看不见。

**第三个（harness 特有）**：`afterAll` 用固定 3s 等子进程，而 harness 在关闭时要落 transcript，
删目录与落盘赛跑 → `ENOTEMPTY`，只在 harness 路径出现。

**规则**：① 测试里"等一个状态"必须有**明确的失败原因**，不能靠超时兜底——超时只说明"没等到"，不说明
"为什么"；② `finally` 必须**停止一切外部进程**，否则失败的代价会被下一次门禁悄悄放大；③ 等子进程
要等 `exit` 事件，不是睡固定秒数；④ 看到"某个测试一直红"，先问"它等的是不是不会发生的事件"。

### D76（2026-10-24）把"未知"编码成 0 的默认值，会在下游变成一句谎言，而且不报错

**现象**：自定义 provider 注册时 `cost: {input:0, output:0, ...}`，于是每一局的自定义端点 都报 `costTotal=0`。分数卡照常算 `mean(cost)` ⇒ 报告写"每局 $0.00"，看起来像"免费"。 没有任何一处报错：0 是一个合法的数字，而"没测到"与"测到 0"在类型上没区别。

**根因**：价格的**可得性**没有单独表达——数字里塞不下「我不知道」。**修法**：加 `costKnown`（模型是否有价目表），
让所有消费者自己决定（分数卡排除、看板写 `unknown`）。**关键是把旗帜放在它限定的数字旁边**（`usage.costKnown`）：
我第一版放在 telemetry 的 `brain` 上，而会话 meta 的 `usage` 是逐字段复制的 ⇒ 页面读不到，又是一次「本地对、下游丢」。

**规则**：① 任何来自外部/配置的数值，先问"这个 0 是测量还是缺省"；是缺省就必须有伴随 标志或 `null`；② 聚合函数（mean/sum）遇到"未知"要**排除并声明**，不能当 0 吞掉；
③ 标志要与数值**同层存放**，跨层复制必然丢（参见 D74）。

### D77（2026-10-24）一个事实有两个"命名器"时，只改一个会把旧名字留在报告里

**现象**：P4 给"为什么这局停了"新增了 `token_cap`/`cost_cap`。`classifyOutcome`（数据层）改完就 测过了；但报告里的排除原因走的是 **另一个** 函数 `metricExclusion`，它仍返回 "horizon not reached"——`classifyOutcome=token_cap`、`metricExclusion="horizon not reached"`。

**根因**：同一个语义（停止原因）被两处各自实现，没有共同的谓词。D74 说的是
"同一份数据被按字段重建"，这里是**同一句判断被写了两遍**——更隐蔽，因为两处都"对"。

**规则**：新增任何一种"具名原因/状态"时，先 `grep` 它的**文案**（不是函数名），列出所有会向用户
展示它的地方（数据分类、报告排除、看板列表），一次改完；能让后者调用前者就调用。

### D78（2026-10-24）把"构建时的快照"当成"现在的事实"：列表不会报错，只会过期

**现象**：Providers 页的模型列表"总是旧的"。不是缓存坏了：列表来自 pi-ai 包内置的**目录快照**（`getBuiltinModelDataGeneratedAt()` = 2026-09-04），而 `Models.refresh()` 对**静态** provider **直接跳过**——根本没有刷新路径；更糟的是 `buildCatalogBrain` 会拒绝快照里没有的模型 id，新模型连"手动输入"都用不了。 **根因**：把随代码发布的数据当成了随世界变化的事实。它永远"有值"，所以永远不会报错。

### D79（2026-10-25）"预览 = 记录"的验收要求**记录里真的有那个字段**；缺了就先补记录

**现象**：B2 要"页面预览与跑完的 manifest 逐字段相同"。写完预览才发现 manifest 里**没有**
`model / api / contextWindow / costKnown`（只有 `servedModel / backend / thinkingLevel /
toolBudget / scaffoldHash / payload* / tokenLimit / costLimit`）⇒ "逐字段相同"要么不成立，
要么变成"只对一部分字段"。

**根因**：预览（事前）与 manifest（事后）是**两个投影**；"逐字段相同"是它们之间的**契约**，
而契约要求**双方字段集对齐**。字段集不对齐时，最省事的做法是悄悄把预览缩到 manifest
现有的字段——于是"模型/上下文窗口"这类信息在预览里消失。

**规则**：① 凡是要"逐字段对照"的两个投影，**先对齐字段集**（缺的补到记录里，而不是从
预览里删）；② 记录里缺的事实要**从解析器取**（不是从配置文件抄）；③ 事后才知道的事实
（provider 实际服务的模型、payload 指纹）**明确排除**在预览之外，并写清"为什么不能预告"。

### D82（2026-10-25）会被**整体替换**的 hook：只有一处构造，否则功能会"跑起来就没了"

**现象**：B3 的因果时间线端点在**空闲看板上有、一局 run 开始后就没了**（404 "timeline disabled"）。所有单测都绿——因为**没有任何测试会"先起 server、再起 run"**。 **根因**：runner 启动时调 `web.attach({sessions})`，而 `attach` 是**整体替换** session hook；
runner 那份是更早写的、窄一点的一份（没有 timeline），于是"只有 server 有的端点"在 run

### D83（2026-10-29）产生动作的控件藏进"有结果才显示"的区块 = 死路

**现象**：B4 把"选两个模型"的控件放进了 `x-show="comparison()"`（有配对结果才显示）的区块：初次打开没有结果 ⇒ 整个区块隐藏 ⇒ **用户看不见选择器**，永远产生不了一次比较。探针直接勾选隐藏的 checkbox 反而"通过"了——它验证的是"DOM 里有"，不是"用户看得见"。 **根因**：把**产生结果的控件**与**显示结果的区块**放在一起 ⇒ "还没有结果"时，连产生结果的办法也一起没了。
**规则**：① 产生动作的控件**永远可见**（结果区可以先空着）；② 探针要断言控件**可见**（`getBoundingClientRect()` 非零），不只是 DOM 里有它；③ 截图看**用户第一眼**那屏——"空区块"常常就是藏起来的控件。

### D84（2026-10-29）面板取了一个**从未存在**的端点 = 永远空的图 + 一句谎话

**现象**：History 的 TRAINING 面板从 2026-10-08 起就显示「no metrics ledger yet —— 局结束时才追加一行」，而**账本里明明有行**。它取的是 `/api/metrics` —— **那个端点从来没存在过**（账本一直挂在 `/api/evolution` 的 `metrics` 字段），于是页面一直在读 404。 **根因**：「端点不存在」和「端点返回空」在页面看来**一模一样**（都没有点可画），于是空态文案把「读不到」说成了「没有」。**空态文案本身是一个断言**，必须和它声称的事实同源。
**规则**：① 面板的取数端点要**真的存在**——加端点时把页面的 fetch 一起改；② 空态文案不许替通道说话（「没读到」≠「没有」）；③ 一个长期「空」的图表要么有人报、要么它其实没在工作。

### D85（2026-10-30）"孤儿符号"报告里的孤儿，常常只是**没被调用过**——别照着删
**现象**：每次 pre-commit 都报 25 个「零引用的内部符号」（前端 `common.js` 的 22 个 `window.UI` 导出 + `defaultLauncher`），**它们全都在用**——调用点在 HTML 模板的 Alpine 表达式里，和别的 js 的 `U.fmtInt(...)`。 **根因**：那个分析器**只数调用**，不数普通引用；前端脚本之间没有 import 绑定（无构建链的普通 script），所以 `U.fmtInt(...)` 连不到 `common.js` 里的定义——改成显式的 `fmtInt: fmtInt` **也不算数**（实测，孤儿数不变）。
**规则**：① 这类报告是**咨询性**的（不拦提交），先分清「真死代码」与「只被调用但看不见」；② 前端 `window.*` 导出**不许照着删**——先 `grep` 模板与别的 js；③ 工具侧没有 ignore 配置（`.pi-shazam/config.json` 只认 `verify.maxFiles`），要根治得工具支持。

### D92（2026-11-02）"页面没做"往往是**跑着的进程比磁盘旧**：路由表不该手写
**现象**：用户报"导航点'比较'/'配置'全是 not found"。页面在磁盘上、代码也写好了，**真因是两个 `--serve` 进程是 10 月 25/27 启动的**：静态文件每次请求都重读（新），**路由表却在进程内存里**（旧）⇒ 新页面不在旧路由里 ⇒ 浏览器只看到一句 `not found`，看起来像"功能没开发"。**根因**：手写路由表 + 长跑进程 = 两份会漂移的事实；且"not found"这种回答**不区分**"地址写错"和"页面没做"和"进程过时"。**规则**：① 路由**由文件名派生**（`pages/<name>.html` ⇒ `/<name>`），"加页面 = 加文件"，不可能出现"文件在、路由没有"；② 不是页面的 URL 必须回答**页面清单 + "进程可能比磁盘旧，请重启"**，不能只回 `not found`；③ 验收要**逐个导航点过去**（smoke 现在走四个页面），只测首页永远发现不了这类问题；④ 改了页面/脚本后，**长跑的服务要重启**——静态文件会热更，路由不会。

### D91（2026-11-01）把一个**模型生成的字符串**当身份，门槛就永远不可达
**现象**：策略卡要求"同一模式被 ≥2 局验证"才入库，而库里的卡始终每局一张新卡。**根因**：`strategyId(action, params)` 对模型写的自由文本＋**全部**参数做哈希——换个镇号、换个措辞就是新身份 ⇒ 跨局累积在结构上不可能，门槛从未真正生效。**规则**：① **身份归代码所有**：封闭词表（与动作目录同源）＋白名单参数，其余字段是证据不是身份；② 模型能"提名"模式，但不能决定"这是不是新卡"；③ 写不存在的动作名要被**拒绝并交回词表**（可观测）；④ 判据类改动先问"这个门槛在数据形状上可达吗"，不可达的门槛等于没有门槛。
